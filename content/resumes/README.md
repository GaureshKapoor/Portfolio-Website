# Resumes — Four Tracks

Gauresh maintains **four resumes at once**, one per job-search track. They share the same underlying record
(the rest of `content/`) but differ in ordering, emphasis, bullet framing, and which experiences get cut.

These files are working documents. They are **never imported by the app** — same rule as every other file in
`content/`. The site renders from `about.md`, `experience.md`, `projects.md`, etc.

## The four tracks

| File | Track | Target roles |
| --- | --- | --- |
| `applied-ai-fde.md` | **Applied AI / FDE** | Forward Deployed Engineer, Forward Deployed Strategist, AI Product Manager / Technical PM, Applied AI / Solutions Architect, Strategic Projects Lead |
| `finance-fintech.md` | **Finance / Fintech** | Fintech product, PE/VC-adjacent technical roles, quant-leaning analytics |
| `product-swe-tech.md` | **Product / SWE / Tech** | Product Engineer, Software Engineer, Founding Engineer, Product Manager |
| `strategy-ops-growth.md` | **Strategy / Ops / Growth** | Strategy & Operations, BizOps, Chief of Staff, Growth |

## Which one the site follows

**As of August 2026, the site and the rest of `content/` track the Applied AI / FDE version.**

That is the active search. `about.md`, `experience.md`, `projects.md`, and `skills.md` are written to match its
positioning — engineer-forward, production and customer-environment framing, shipped 0→1 products elevated.
When the primary track changes, say so explicitly and the site content gets re-synced to the new one.

The canonical positioning line for the current track lives at the top of `applied-ai-fde.md`.

## Working on a resume

Go section by section rather than rewriting whole documents. Each file keeps its own notes block at the bottom
recording claims that need verification, open decisions, and what changed from the prior version.

Keep numbers consistent across all four files — if a metric is restated or corrected in one, fix it in the rest.
